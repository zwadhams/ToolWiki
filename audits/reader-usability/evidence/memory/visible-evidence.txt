6. AddressSanitizer recovery
http://127.0.0.1:4353/ToolWiki/tools/address-sanitizer/
What you need: C or C++ source, a supported Clang toolchain, permission to rebuild
and run tests; compile and link with instrumentation.
Example label: Illustrative example, not run here.
Visible bounds.c:
#include <stdlib.h>
int main(void) {
    int *values = malloc(2 * sizeof(*values));
    if (!values) return 1;
    values[2] = 7;
    free(values);
    return 0;
}
PowerShell instructions identify clang, its C linker/libraries and matching
AddressSanitizer runtime; explicitly distinguish clang from clang-cl.
Command:
clang -O0 -g -fsanitize=address -fno-omit-frame-pointer bounds.c -o bounds.exe
.\bounds.exe
The page asks the reader to confirm target/runtime architecture compatibility.
Representative report outline, explicitly not captured output:
ERROR: AddressSanitizer: heap-buffer-overflow
WRITE of size 4
#0 main ... bounds.c:5
... allocated ...
#0 ... malloc ...
#1 main ... bounds.c:3
Explanation: access stack points to the write, allocation stack to the two-element
allocation; index 2 is outside it; indices 0 and 1 are valid; correct and repeat.
Clean-run limit: it checks instrumented code that runs; unexecuted paths remain
unchecked and not every memory error is covered. Retain flags/workload/suppressions.
