**Start with the task you need to complete and the material you can provide.** The catalog helps you choose a tool; profiles and guides help you prepare and interpret a check.

## Choose a tool for a known task

1. Open [Find a tool](../../) and use a task shortcut or search for a tool, language, or capability. Combine language and input filters: Python source analysis and Python dependency scanning answer different questions.
2. Read a candidate's setup, result, and limits. [Compare tools](../../compare/) when you have two or three candidates, and check cost and edition details before choosing a workflow.
3. For several components or interfaces, use [Find tools for your system](../../analysis-suite/). Its candidates reflect reviewed prerequisites. Answer missing questions and check compatibility notes before treating a suggestion as ready to run.
4. Follow the profile's first-result procedure or a [worked Python workflow](../python-checks/). Keep a [run record](../run-record/) and [review the findings](../reviewing-findings/).

If you know the tool's name, search for it directly. Catalog search covers tool metadata; **Search all pages** also finds guide and profile text. Global sidebar category links start a fresh category view; category tabs above catalog results keep your current filters.

## Learn enough to choose

Start with [static versus dynamic analysis](../../concepts/static-vs-dynamic/), then follow the route that matches your input:

- [Static analysis approaches](../../concepts/static-approaches/) separates source, binary, dependency, and configuration checks.
- [Ways to do DAST](../../concepts/dast-approaches/) explains testing a running application.
- [Verification and generated tests](../../concepts/verification-and-generated-tests/) distinguishes a proof, a counterexample, and a test result.

For a concrete choice, use the [Java](../java-analysis/), [memory-error](../memory-error-detection/), or [temporal monitoring](../temporal-monitoring-and-falsification/) guide. [Research notes](../../research/) explain study findings and their limits.

## Read the evidence labels

A profile's verification date records documentation review. It is not a benchmark or proof that the example ran on your machine. Examples identify whether they are illustrative or executed; execution records name the environment and artifacts. Record your choice and unresolved prerequisites in an [adoption note](../choosing-and-recording-tools/).
