## Where it fits

AddressSanitizer adds a memory-error detector to executions generated by tests or fuzzers. It pairs naturally with [AFL++](../afl-plus-plus/) or [libFuzzer](../libfuzzer/).

## Worked example: an out-of-bounds write

**Illustrative example, not run here.** With Clang and its sanitizer runtime installed on a supported host, save `bounds.c`:

```c
#include <stdlib.h>
int main(void) {
    int *values = malloc(2 * sizeof(*values));
    if (!values) return 1;
    values[2] = 7;
    free(values);
    return 0;
}
```

Build and run this small test in a Unix-style shell:

```sh
clang -O0 -g -fsanitize=address -fno-omit-frame-pointer bounds.c -o bounds
./bounds
```

The intended result is a heap-buffer-overflow report for the write past the two-element allocation. Inspect the reported access and allocation locations. Correct the index to an allocated element and repeat.

## Interpret coverage

A successful execution only covers the behavior that ran. Keep the build flags, workload, and suppression settings with the report.

See [memory-error detection](../../guides/memory-error-detection/) to compare an instrumented build with static checking and Memcheck's executable instrumentation.
